# FixLog — project memory for Claude

"When did I last service/fix this?" — maintenance history + live dashboard for
home systems, appliances, vehicles and personal belongings.

Read first (they're short): `docs/REQUIREMENTS.md` (what & why, FR/NFR ids),
`docs/ARCHITECTURE.md` (how, data model, ADRs), `SECURITY.md` (threat model).
Don't re-derive these — update them when behaviour changes.

## Stack (versions matter — APIs differ from older training data)

- **Next.js 16** App Router + Turbopack. Middleware is `src/proxy.ts` (not `middleware.ts`).
  `params`/`searchParams`/`cookies()` are async. Page/layout props use global `PageProps<"/route">` /
  `LayoutProps<"/">` (generated by `next typegen`). Bundled docs: `node_modules/next/dist/docs/`.
- **Clerk Core 3** (`@clerk/nextjs` v7): `<Show when="signed-in">` replaces `<SignedIn>`; server `auth()` from
  `@clerk/nextjs/server`; `clerkMiddleware` also emits the strict nonce CSP.
- **Supabase** via third-party auth: the Clerk session token is passed as `accessToken`; RLS checks
  `auth.jwt()->>'sub'` against `user_id` (text). No Supabase Auth, no JWT templates.
- **Zod 4** (`z.iso.date()`, `z.uuid()`, `z.flattenError`). Optional form fields: union + `.optional()`
  (a union containing `z.undefined()` is NOT optional for a missing key).
- Tailwind v4 (tokens in `src/app/globals.css`, `@theme inline`), lucide-react, date-fns v4.

## Layout

- `src/lib/` pure/shared logic: `catalog.ts` (categories/types/suggested tasks), `domain.ts` (urgency,
  intervals, health score — unit tested), `validation.ts` (all Zod schemas), `csv.ts`, `ics.ts`.
- `src/lib/supabase/server.ts` → `getSupabase()` per-request client + userId (RLS client in Clerk mode,
  service role in demo mode). `admin.ts` (service role) is used only there, in the Clerk webhook and in
  `/api/health`'s schema check.
- `src/server/queries.ts` reads; `src/server/actions/*.ts` mutations (`"use server"`), all through
  `mutationContext()` (auth + rate limit). After a mutation call `revalidatePath("/", "layout")`.
- `src/app/(app)/*` authenticated pages; `src/components/ui` primitives; `src/components/features` feature UI.
- `supabase/migrations/*.sql` schema + RLS; `supabase/tests/rls_test.sql` must cover new tables.

## Rules

- Every new table: `user_id text not null default public.requesting_user_id()`, RLS enabled + forced,
  owner policies for each verb, `enforce_same_owner` trigger if it references a parent, and RLS tests.
- Auth mode (`src/lib/auth-mode.ts`): `clerk` | `demo` (no Clerk + `DEMO_MODE=true`, service-role client,
  shared `demo_user`) | `unconfigured` (setup page). Because demo bypasses RLS, EVERY query/mutation in
  `src/server/` must also `.eq("user_id", userId)` / set `user_id` explicitly. Never call Clerk's `auth()`
  directly outside `src/lib/supabase/server.ts` — use `getSupabase()` / `getCurrentUserId()`.
- Never trust ids from the client: validate with `idSchema`; parse all input with Zod (objects strip
  unknown keys — never spread raw FormData into an insert).
- Never log or return raw DB errors to the client (`dbError()` helper). Never use `dangerouslySetInnerHTML`.
- Urgency/overdue is derived from dates (`getUrgency`) — never store it. "Today" comes from `getToday()`
  (user timezone cookie).
- Colours: use tokens (`text-ink`, `bg-surface`, `text-critical-ink`…); status colours always paired with
  an icon + label.
- Keep client components small; data fetching stays in server components.

## Commands

```bash
npm run dev          # local dev (needs .env.local — see .env.example)
npm run check        # lint + typecheck + unit tests  ← run before every commit
npm run build        # production build (CI uses placeholder env)
npm run test:db      # migrations + RLS tests (needs DATABASE_URL to a throwaway Postgres)
npm run format       # prettier
npm run db:new name  # new migration; npm run db:push to apply to linked project
```

## Git / CI

- Work on feature branches → PR → `main`. CI: format, lint, typecheck, unit, build, audit, DB/RLS tests,
  gitleaks, CodeQL, dependency review. Merging to `main` deploys (migrations → Vercel prod → `live` branch).
- Don't edit `live` directly; it is fast-forwarded by `.github/workflows/deploy.yml`.
